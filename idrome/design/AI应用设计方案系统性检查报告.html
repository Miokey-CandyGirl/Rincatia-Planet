2.2 Edge Function 中 hashPassword 函数被注释，调用将报 ReferenceError

第 32 章 line 5364-5372

问题描述：分享链接生成 Edge Function 中，line 5364 调用了 await hashPassword(password)，但该函数的实现（line 5366-5372）被包裹在注释中。部署执行时将抛出 ReferenceError: hashPassword is not defined，分享功能完全不可用。

修复建议： 取消注释，将 hashPassword 定义为可执行函数。同时建议使用更安全的哈希算法： 
// 使用 Web Crypto API 的 PBKDF2 替代 SHA-256（更安全）
async function hashPassword(password) {
  const salt = crypto.getRandomValues(new Uint8Array(16))
  const keyMaterial = await crypto.subtle.importKey(
    'raw', new TextEncoder().encode(password), 'PBKDF2', false, ['deriveBits']
  )
  const hash = await crypto.subtle.deriveBits(
    { name: 'PBKDF2', salt, iterations: 100000, hash: 'SHA-256' }, keyMaterial, 256
  )
  return Array.from(salt).map(b => b.toString(16).padStart(2,'0')).join('') + ':'
    + Array.from(new Uint8Array(hash)).map(b => b.toString(16).padStart(2,'0')).join('')
}

3.1 Proxy 状态管理缺乏深层响应式，嵌套变更不会触发 UI 更新

第 31 章 line 5088-5120

问题描述：makeReactive 函数仅代理顶层对象，注释声称"递归代理嵌套对象"但实现并未递归。关键缺陷：

  • state.conversations.push(newConv) — 不会触发监听器（push 修改的是原始数组，非 Proxy）
  • state.messages[i].content = 'new' — 不会触发监听器（嵌套属性修改）
  • state.currentUser.name = 'x' — 不会触发监听器

在 AI 对话应用中，消息列表的 push/更新是最频繁的操作。此缺陷将导致流式消息渲染、对话列表更新等核心 UI 不会自动刷新。

修复建议： 增加 get 拦截器返回代理后的嵌套对象，set 时对新对象值递归代理： 
const makeReactive = (obj) => {
  return new Proxy(obj, {
    get(target, key) {
      const val = target[key]
      if (val && typeof val === 'object' && !val.__isReactive) {
        return makeReactive(val)
      }
      return val
    },
    set(target, key, value) {
      const oldValue = target[key]
      target[key] = value
      if (oldValue !== value) {
        listeners.forEach(fn => fn(target, key, value, oldValue))
      }
      return true
    }
  })
}
注意：数组 push/splice 仍需额外处理。建议覆盖数组方法或使用 state.conversations = [...state.conversations, newConv] 模式触发更新。

3.2 shared_conversations RLS 策略允许任何人读取所有行的 password_hash

-- 仅保留用户管理自己分享的策略
-- 分享访问通过 Edge Function（service_role 绕过 RLS）处理
方案 B：仅暴露非敏感列，通过视图实现： 
CREATE VIEW shared_conversations_public AS

4.3 PDF 导出依赖浏览器 print API，导出结果不可控

第 32 章 line 5254-5271

PDF 导出使用 window.print() + 打印 CSS，依赖用户在打印对话框中选择"保存为 PDF"。此方案无法控制输出文件名、页边距、纸张方向等，不同浏览器行为不一致。移动端浏览器普遍不支持打印对话框，功能在移动端不可用。

P2

4.4 密码哈希使用 SHA-256，强度不足

第 32 章 line 5366-5372

分享密码使用 SHA-256 + 随机盐。虽然加盐后比纯 SHA-256 更安全，但 SHA-256 速度快，容易被暴力破解。对于密码存储，应使用专门的密码哈希函数（PBKDF2、bcrypt、Argon2）。

修复建议：改用 Web Crypto API 的 PBKDF2（已在 P0-2.2 修复建议中给出代码示例），迭代次数不低于 100,000 次。Deno 环境原生支持 crypto.subtle.deriveBits。
